# 数据刷新与质量检查机制

## 刷新入口设计

项目建立了统一三级运行入口：`py/run_pipeline.py`。

三级入口分别是：

- `quick`：只读诊断，不刷新数据库、不写质量历史、不更新记忆快照。
- `module`：只刷新目标模块及必要下游，默认只做即时检查。
- `full`：正式 14 步全链路、成本缺失报告、质量历史和动态记忆快照。

这种设计避免了每次小排查都重跑完整链路，也避免了未经正式验收的中间状态污染治理历史。

## 常用命令

```powershell
python D:\powerbi项目\py\run_pipeline.py quick --module all
python D:\powerbi项目\py\run_pipeline.py module --module coop --dry-run
python D:\powerbi项目\py\run_pipeline.py module --module coop
python D:\powerbi项目\py\run_pipeline.py full
```

## 长期脚本分类

长期脚本应放在 `py/` 或 `sql/` 下，例如：

- `py/run_pipeline.py`
- `py/full_refresh_and_export_cost_missing.py`
- `py/run_sql_file.py`
- `py/load_sku_mapping_to_db.py`
- `py/load_cogs_from_cost_files_to_db.py`
- `py/import_promo_spend_files_to_db.py`
- `py/audit_channel_labels.py`
- `py/run_governance_checks.py`
- `py/refresh_memory_snapshot.py`

临时排查脚本可以放在 `tmp_*.py` 或 `tmp_scripts/`，但如果逻辑未来还要复用，就应迁移为正式脚本。

## 每次全链路刷新后必查

1. 最终表 `date + asin` 是否重复。
2. SalesAmt 是否异常变化。
3. Ads 标准 ASIN 源表金额是否等于最终表金额。
4. Promo 标准 ASIN 源表金额是否等于最终表金额。
5. 有销售额但 coop_rate = 0 是否为 0。
6. 成本缺失销售额。
7. Mapping not found / PL 缺失 ASIN。
8. Inventory matched 但 dimension missing 的 SKU。
9. 仓储费按 physical_sku 复算是否等于最终表。
10. VC 专属事实表是否全部为 `channel = 'Amz VC'`。
11. `bi_sku_mapping` 是否仍存在 `Amazon` / `Amazon VC` 旧标签。
12. `bi_sku_channel_mapping` 的 `channel + main_sku + channel_sku` 是否重复。

## 质量等级

- 唯一键、PL、Coop、负仓储费、渠道、Ads / Promo 金额守恒和 Mapping 重复属于 ERROR。
- 已知成本缺失可作为 WARN，但要保存影响行数和销售额。

## 中文路径和编码经验

项目默认存在中文路径、中文文件名、中文 sheet 名、中文字段名和中文 SQL / Excel 别名。长期脚本必须按这个前提设计：

- 显式使用 UTF-8。
- 使用 `pathlib.Path` 处理路径。
- 用 `sys.argv` / `argparse` 接收中文路径参数。
- 避免在 PowerShell heredoc 或 `python -` stdin 中硬编码中文路径、sheet 名和字段名。
- PowerShell 展示乱码时，先用 UTF-8 重新读取验证，不要直接判断源文件损坏。
