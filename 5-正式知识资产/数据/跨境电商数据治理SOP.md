# 跨境电商数据治理 SOP

> 目标：让每一批经营数据都能回答“从哪里来、代表什么、适用于哪里、如何验证”。本 SOP 是工作版，正式上线前需要与数据库治理规则、项目记忆和当前状态快照核对。

## 1. 适用范围

适用于 Amazon VC/SC、Walmart 等平台的销售、广告、促销、库存、成本、费用、Mapping 和利润数据。

## 2. 数据入库前

### 2.1 登记来源

为每个来源登记：

- 来源名称和系统
- 平台、账号、市场和币种
- 业务范围和业务模式
- 获取方式
- 更新频率和 SLA
- 数据粒度
- 日期语义
- 责任人
- 导入脚本或文件路径

### 2.2 接收文件

- 文件进入登记过的 source 目录。
- 保留原始文件，不直接覆盖。
- 计算 SHA-256。
- 记录文件名、批次号、导入时间、报告起止日期和行数。
- 已存在的同源同哈希文件默认拒绝重复导入。

## 3. 技术标准化

检查并处理：

- 字段名称和类型
- 日期、时区和日期语义
- 币种、金额和汇率
- 空值、重复、异常值和负数
- 平台、站点、账号编码
- 必填字段
- 文件列结构变化

原则：这一阶段解决“数据能不能正常用”，不在这里决定复杂的业务归属和分摊口径。

## 4. 业务口径治理

每个新事实表或指标必须明确：

- `channel`
- `business_scope`
- `source_system`
- `grain`
- `date_semantics`
- `currency`
- `account/vendor`
- `market`

特别区分：

- VC retail/endpos 与 VC supply/order
- PO、DF、DI 与顶层渠道
- 共享库存、原始成本、Kit、NS Mapping 与渠道专属事实
- 订单、发货、结算和 Retail 销售口径

## 5. 主数据与 Mapping

维护并检查：

- SKU / ASIN / MSKU / FNSKU / 内部 SKU
- 父子 SKU
- Kit / Bundle 与子件数量
- 平台、账号、店铺和站点
- 供应商、品类、负责人
- 费用类型和分摊规则

缺失 Mapping 必须产生质量问题，不得静默归入未知或错误对象。

## 6. 加工与建模

建议按以下层次管理：

- ODS：保留原始来源和批次
- DIM：维护主数据和映射
- DWD：标准化明细事实
- DWS：业务主题汇总
- ADS：面向 Power BI、预警和管理应用

复杂清洗、Mapping、分摊和利润计算尽量放在数据库或数仓，不重复堆在 Power BI 报表层。

## 7. 质量检查

每次导入或刷新至少检查：

- 文件是否到达
- 日期范围是否正确
- 是否重复导入
- 必填字段是否缺失
- Mapping 是否缺失
- 成本和汇率是否缺失
- 金额、销量和费用是否异常波动
- 主键是否唯一
- 来源与结果是否守恒
- 渠道标签是否正确
- 结果是否能与平台、ERP 或财务账单对账

## 8. 状态与处理

- `PASS`：通过，可以进入下游。
- `WARN`：存在可接受问题，记录影响范围并通知责任人。
- `FAIL`：阻断下游发布，先修复或取得明确豁免。

每次质量运行记录：规则、时间、批次、状态、影响行数、影响金额、错误信息和处理人。

## 9. 特殊规则

特殊映射、默认扣点、月份例外和人工调整必须有：

- 规则编号
- 规则内容
- 原因和来源
- 生效范围
- 优先级
- 关联变更单
- 验证记录
- 回滚或历史重算判断

未经确认的经验不得升级为通用规则。

## 10. 发布前验收

- [ ] 口径已由业务和数据负责人确认。
- [ ] 核心来源与结果已对账。
- [ ] 质量检查通过或 WARN 已批准。
- [ ] 权限范围已验证。
- [ ] 刷新日志完整。
- [ ] 变更、规则和版本已登记。
- [ ] 当前状态快照已更新。
- [ ] 业务用户知道如何使用和反馈。

## 11. 失败处理

发现数据错误时按顺序：

1. 保留错误批次和原始证据。
2. 判断是来源、技术清洗、Mapping、口径、分摊还是展示问题。
3. 阻断受影响下游，避免错误扩散。
4. 修复并记录变更。
5. 重新运行质量检查和必要的历史回算。
6. 更新状态快照、规则登记和变更记录。

## 12. 本 SOP 的当前边界

本文件是由 Vault 中已有资料合并出的工作版，不代表外部 `D:\powerbi项目` 当前数据库的自动同步状态。涉及生产数据和财务口径时，以用户最新确认、当前状态快照和正式规则总表为准。
