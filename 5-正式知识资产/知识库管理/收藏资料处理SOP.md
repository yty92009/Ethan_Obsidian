# 收藏资料处理 SOP

> **目的**：把"从收藏到知识资产"的标准处理流程固化为可重复执行的步骤，保证任何 AI 会话按同一套规则处理，产出质量稳定、可审核、可追溯。
> **适用范围**：`7-收藏资料/Clippings/` 中所有新剪藏，及历史剪藏的补处理。
> **来源**：整合《知识库管理项目说明》§6/§7/§8/§13、项目记忆 §1.1 价值基准、2026-11-09 确认的图片分级策略与分支汇总页机制。
> **状态**：draft——各规则已经用户分别确认，本文档为首次整合，待用户整体确认后转 active。

## 0. 角色边界

| 角色 | 做 | 不做 |
| --- | --- | --- |
| AI | 初筛选级、图片分级、卡片起草、原文迁移执行、汇总页更新、链接与格式校验 | 代填个人经历与业务数字、删除原文、未经确认转 active、凭标题下结论 |
| 用户 | 定级争议裁决、卡片与资产确认、个人事实补充、发布批准 | —— |
| 脚本 | 下载、哈希、批量改写、格式校验 | 语义判断 |

## 1. 收藏价值基准（定级依据）

新剪藏初筛按六域基准定级，不再临场猜测：

| 兴趣域 | 范围 | 默认待遇 | 迁移去向 |
| --- | --- | --- | --- |
| **数据** | 获取/开发/治理/平台/中台/语义层 | S/A 完整卡 | `1-数据/` |
| **BI** | PowerBI、可视化、报表工程 | 核心 S/A；操作技巧 B | `2-BI/` |
| **AI** | Agent/LLM 应用、RAG、AI 问数 | S/A | `3-AI/` |
| **经营** | 经营分析、跨境电商 P&L、广告运营 | 工作相关 S/A；泛观察 B | `4-数据分析/` |
| **工具技巧** | 提效工具、配置、导航 | B 用时查，极简或合并卡 | 按用途入 2-BI 或 3-AI |
| **新兴事物** | 新趋势、行业动态 | B/C 浏览型，值得跟进的记一笔 | 按最接近领域归档 |

定级补充判断：**阅读原文再定级**——标题会骗人（案例：「AI 人格」实为 SparkX 广告工具文档）。

## 2. 处理流程（九步）

### 步骤 1：初筛与完整度检查

- 逐篇读原文，对照价值基准定级（S/A/B/C）。
- 完整度检查：正文字数、图片占比——纯图片文标记 `verification_status: incomplete_source`，只做占位卡，不强行总结。
- 批次用明确文件清单，不用历史数量代替。

### 步骤 2：图片分级（防图床失效）

判断标准：**图片是否承载"离开就无法理解的独特信息"**。

| 层级 | 对象 | 处理 |
| --- | --- | --- |
| 备份 | key 级原文、incomplete_source、"图片即内容"的文章 | 图片下载到该笔记目录 `attachments/<文章名>/`，引用改本地相对路径，纳入 git |
| 转文字 | 步骤截图、装饰图、导航图、logo | 移除图床外链；有意义的 alt 转为 `（图：alt）`；文章级标注注明原图数量 |

要求：下载带浏览器 UA；失败保留原链接并记录清单，不静默丢弃。

### 步骤 3：生成处理卡片

- 位置：`8-知识库管理/Clippings处理/`，编号顺延（当前至 28）。
- 卡片形态：S 级/内容独特 → 单篇完整卡；B 级同主题多篇 → **主题合并卡**（逐篇 2-3 行要点 + 去向）；纯图片文 → 占位卡。
- frontmatter 必备：`type/status/importance/review_priority/source_path/source_url/topic/created/updated/related_notes/next_action/needs_human_review/verification_status`。
- 审核语义：`key` 卡 `needs_human_review: true`（进审核清单）；`spot_check` 卡 `false`（用时核对，不进批量审核）。
- 卡片至少回答：一句话结论、核心观点、对本人价值、关联笔记、建议动作、最小实践与验收、需验证项。

### 步骤 4：人工确认

用户按 [[8-知识库管理/审核清单]] 逐份回复"通过/修改/作废"；AI 执行修改并更新审核属性。**个人经历与业务数字 AI 不代填。**

### 步骤 5：原文迁移

确认后（或按用户指令批量）将原文从 `7-收藏资料/Clippings/` 迁入价值基准对应技能分类；卡片 `source_path` 与相关 README 同步更新；Clippings 处理一个少一个。原文**内容只读不改，只迁位置**。

### 步骤 6：分支汇总页增量更新

原文迁入的分支若已有 `汇总.md`：新增篇目评级、修订统一框架、版本 +1。分支资料 ≥8 篇且无汇总页时，按说明 §4.2 创建。

### 步骤 7：索引与记忆同步

批次 README（Clippings处理/）、分类 README、首页进度、项目记忆——四处同步更新，缺一处即验收不通过。

## 3. 验收清单（每批次结束核对）

- [ ] 输入清单与实际文件一致，每篇有明确去向（卡/极简/待归档）
- [ ] 每张卡映射具体来源；key/spot 标记与 importance 一致
- [ ] 图片按策略处理：备份有本地文件、转文字无残留外链（`grep "https://` 复查）
- [ ] 原文迁移后链接复检通过，`source_path` 全部指向新位置
- [ ] 分支汇总页已更新（若该分支已有汇总页）
- [ ] 四处索引同步；首页进度反映本批结果
- [ ] incomplete_source 单列，不计入完整处理数
- [ ] git 提交并推送远程

## 4. 红线（任何情况下不做）

1. 不修改剪藏原文内容（只迁位置）；不以"去重/清理"为由删除原文。
2. 不代填个人经历、项目数字、业务口径——占位标注"待补"，由用户填写。
3. 不把外部文章观点写成用户经验；不把推广内容当事实（注明推广属性）。
4. 不绕过 GitHub Push Protection（遇密钥拦截 = 排除文件或脱敏，不强行推送）。
5. 未经用户明确确认，不把 draft 转 active、不改正式资产。
