# 广告促销费用进入利润表规则

## 核心问题

广告和促销费用经常与销售事实不完全同步。某些 ASIN 可能没有销售但有广告或促销费用，如果主表 spine 只来自销售表，这部分费用就无法进入利润表。

当前项目已经把 sales ASIN、ads ASIN、promo ASIN 合并成标准 ASIN spine，解决了无销售但有费用的产品进入最终利润表的问题。

## Ads规则

- 源表：`data_market.bi_ads`
- 日期字段：`ad_date`
- ASIN 字段：`advertised_product_id`
- 金额字段：`total_cost`
- 利润步骤：`data_market.bi_profit_calc_05_ads`
- 当前 VC 匹配键：`channel + date + asin`
- 必须先按 `channel + ad_date + advertised_product_id` 聚合，再 join

## Promo规则

- 源表：`data_market.bi_promo_spend`
- 日期字段：`order_date`
- ASIN 字段：`asin`
- 金额字段：`rebate_agreement_currency`
- 利润步骤：`data_market.bi_profit_calc_04_promo`
- 当前 VC 匹配键：`channel + date + asin`
- 必须先按 `channel + order_date + asin` 聚合，再 join

## 手工促销费导入经验

手工促销费新增账单默认应该追加导入，不应轻易删除旧历史。

去重建议分两层：

1. 同一批合并文件内，按 `order_date + asin + amount + source_file + source_sheet + source_row_number` 检查精确重复。
2. 入库时跳过数据库中已经存在的同源文件、同 sheet、同行号、同日期、同 ASIN、同金额记录。

只有明确要重建全部手工促销费时，才使用替换模式。

## 对账规则

刷新后需要检查：

- final ads = valid ASIN ads source
- final promo = valid ASIN promo source
- unmatched source keys 应为 0

注意：源表总金额和最终表金额不一致，不一定是异常。应按标准 ASIN 口径对账，不要把脏 ASIN、日期、金额误填 ASIN 列的数据算作应该进入最终利润表。
