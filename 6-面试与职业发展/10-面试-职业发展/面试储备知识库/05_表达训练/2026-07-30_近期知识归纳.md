## 跨境电商指标知识

### 销售指标

- GMV / 销售额：看规模，但不能代表利润。
- Net Sales / 净销售额：更接近真实经营收入。
- Orders / 订单数：判断交易规模。
- Units / 销量：适合和库存、补货联动。
- AOV / 客单价：反映产品结构、价格带和促销策略。

### 流量与转化指标

- Impressions / 曝光：流量入口规模。
- Clicks / 点击：用户是否被吸引。
- CTR：主图、标题、素材、位置吸引力。
- Sessions：商品页或店铺访问。
- CVR：访问到购买的转化质量。

### 广告指标

- Spend：广告花费。
- Sales from Ads：广告归因销售额。
- ACOS：广告花费 / 广告销售额。
- TACOS：广告花费 / 总销售额。
- ROAS：广告销售额 / 广告花费。

ACOS / TACOS 健康区间：

- 成熟稳定产品：ACOS 15%-30%，TACOS 5%-15%。
- 高毛利产品：ACOS 25%-40% 也可能接受，TACOS 10%-20%。
- 低毛利产品：ACOS 通常要压到 10%-20% 以下，TACOS 5%-10%。
- 新品冷启动：ACOS 30%-60% 甚至更高，TACOS 15%-30% 甚至更高。

面试表达：

> 我不会简单说 ACOS 多少就一定健康。成熟产品 ACOS 一般控制在 15%-30%、TACOS 控制在 5%-15% 比较常见。但核心还是看毛利率和产品阶段。新品期为了拿曝光、评论和排名，ACOS 可以阶段性偏高；成熟品就要看广告有没有侵蚀利润。

### 库存指标

- 可售库存：判断是否会缺货。
- 在途库存：影响补货节奏。
- 库存可售天数：衡量缺货风险和库存健康度。
- 周转率：判断库存资金占用。
- 超龄 / 滞销库存：影响仓储费、现金流和清仓策略。

## Amazon 流量转化漏斗

```text
曝光 -> 点击 -> 商品页访问 -> 加购 -> 下单 -> 支付 / 发货 -> 评价 / 复购
```

分析销售下降时，不要只看销售额，要按漏斗拆：

- 曝光有没有下降。
- 点击率有没有变差。
- Sessions 是否减少。
- 转化率是否下滑。
- 库存和 Buy Box 是否异常。
- 广告 ACOS / TACOS 是否变化。
- 评价、价格、竞品是否影响转化。

## 用户行为分析

### 目的

用户行为分析不是单纯统计点击，而是回答：

1. 用户从哪里来。
2. 用户在哪一步流失或转化。
3. 企业应该对不同用户采取什么运营动作。

### 客户旅程

客户旅程不是一次访问路径，而是客户从触达、访问、转化、购买、复购到流失召回的完整生命周期。

```text
看到广告 / 搜索商品
        ↓
进入网站 / App / 店铺
        ↓
浏览商品 / 搜索 / 看详情页
        ↓
加购 / 收藏 / 领券
        ↓
下单 / 支付
        ↓
发货 / 收货
        ↓
评价 / 退货 / 售后
        ↓
复购 / 会员 / 召回 / 流失
```

### 标签和分群

- 标签：描述用户是什么样的人，例如会员、高频、价格敏感、近 30 天未消费。
- 分群：基于标签和行为条件，把一批用户圈出来做分析或运营。

面试表达：

> 标签是用户画像的基础，回答“这个用户是什么样的人”；分群是运营和分析的动作，回答“我要把哪些人圈出来做分析或触达”。

### CDP

CDP 是 Customer Data Platform，客户数据平台。

核心作用：

```text
多渠道客户数据
        ↓
身份识别 / ID-Mapping
        ↓
统一客户档案
        ↓
标签体系 / 用户分群
        ↓
分析洞察 / 精细化运营
```

面试表达：

> CDP 的核心价值是把分散在不同触点和系统里的客户数据打通，形成统一用户画像，然后支持标签、分群、用户行为分析和精准运营。

### RFM

RFM 用三个维度做用户价值分层：

- R / Recency：最近一次消费。
- F / Frequency：消费频次。
- M / Monetary：消费金额。

适合区分：

- 高价值用户。
- 潜力用户。
- 价格敏感用户。
- 沉睡 / 流失用户。

### AARRR

AARRR 用于看用户增长链路：

- Acquisition：获客。
- Activation：激活。
- Retention：留存。
- Revenue：变现。
- Referral：推荐。

面试表达：

> RFM 更适合做用户价值分层，AARRR 更适合看完整增长链路。饿了么这类 C 端场景可以用 RFM 判断用户价值和红包策略，用 AARRR 看从拉新、首单、复购到长期留存的过程。

## 饿了么 C 端用户分析经验

你可以表达做过或接触过的方向：

- 红包投放规则。
- 用户标签。
- 千人千面。
- 用户是否会员。
- 消费频次。
- 客单价。
- 价格敏感度。

红包投放效果指标：

- 触达人数、触达率、打开率。
- 领取人数、领取率。
- 核销人数、核销率、下单转化率。
- 订单数、GMV、客单价、实付金额。
- 红包补贴金额、单均补贴、补贴率。
- 毛利、净收入、ROI。
- 复购率、留存率、召回率、流失率。

ROI 口径：

```text
销售额 ROI = 红包带来的 GMV / 红包补贴成本
利润 ROI = 红包带来的增量毛利 / 红包补贴成本
```

更严谨的说法：

> 红包投放尤其要看增量效果，最好设置对照组，用投放组和未投放组的订单、GMV、毛利、复购变化来判断真实 ROI。

## AI 与数据分析

### Agent

一句话解释：

> Agent 是能围绕目标自主拆解任务、调用工具、执行步骤并反馈结果的 AI 助手。

更口语：

> 普通 AI 更像问答工具，Agent 更像能连续办事的助手。

### NL2SQL

NL2SQL = Natural Language to SQL，自然语言转 SQL。

解释：

> 用户用普通话提问，系统自动理解问题，并生成 SQL 去查数据库。

落地难点：

- 指标口径。
- 表关系。
- 权限控制。
- 时间理解。
- 字段映射。
- 结果校验。
- 数据安全。

### 对 AI Data Agent 的真实表达

因为你没有完整主导过 AI Data Agent 项目，所以要如实但不自降：

> 我没有完整主导过 AI Data Agent 项目，但我理解它在企业数据分析里的落地逻辑，尤其是指标口径、权限控制、SQL 生成、结果校验和异常归因这些关键环节；我也在日常使用 AI 工具提升 SQL、文档和自动化效率。

## 外部数据资产与海外 C 端产品

### 外部数据资产地图

不是简单数据源清单，而是要管理：

- 数据来源。
- 覆盖国家 / 市场。
- 数据主题。
- 数据粒度。
- 更新频率。
- 历史周期。
- 字段口径。
- 供应商。
- 接入方式。
- 成本。
- 质量评分。
- 使用场景。
- 负责人。

### 外部数据评估

重点看：

- 覆盖度。
- 粒度。
- 准确性。
- 稳定性。
- 时效性。
- 可接入性。
- 合规性。
- 成本收益。

面试表达：

> 外部数据不能直接拿来用，要先做口径标准化和可信度评估，再和内部市场、渠道、产品、用户等主数据进行映射。很多外部数据更适合看趋势和结构，而不是作为财务级准确数据。
