### 一句话解释 Agent

> Agent 可以理解为一个能围绕目标自主拆解任务、调用工具、读取数据、执行步骤并反馈结果的 AI 助手。

更接地气的说法：

> 普通 AI 更像问答工具，Agent 更像能帮你连续办事的助手。比如你让它分析一份经营数据，它不只是回答一句话，而是可以自己读取文件、检查字段、写 SQL、生成图表、总结异常，并把结果整理成报告。

### AI 相关推荐回答

> 我理解 AI 对数据分析岗位的影响，主要是把很多重复性工作提效，比如 SQL 辅助、数据清洗、文档整理、指标解释、自动化流程设计和经营总结。但数据分析的核心不会完全被替代，因为业务问题怎么定义、指标口径怎么统一、异常结果是否可信、最终建议能不能落地，这些仍然需要人的业务理解和判断。
>
> 我自己现在也会使用 Claude Code、Codex 这类工具辅助整理项目、梳理 SQL 和自动化思路。我的态度是把 AI 当成效率工具，而不是直接把 AI 输出当结论。尤其在数据分析场景里，AI 生成的结果必须回到数据源、业务口径和校验逻辑里验证。

## 重点问题回答草稿

### 1. 为什么看神策这个岗位？

> 我看这个岗位，主要是因为它不是单纯做内部报表，而是更强调理解客户业务问题，再通过指标体系、数据采集、分析应用和产品赋能帮客户把数据用起来。
>
> 我过去几年在跨境电商做数据体系建设，很多工作其实也是这个逻辑。比如业务一开始不是缺图表，而是销售、库存、广告、费用、利润这些数据分散，口径不一致，管理层和运营很难快速判断问题。我做的事情就是先梳理业务目标和指标口径，再整合数据、建设模型、开发 BI、做预警和自动化，最后让业务团队形成日常使用机制。
>
> 所以我觉得我的经历和这个岗位有比较强的迁移关系。区别是过去更多服务内部业务团队，神策这里是服务外部客户，但底层能力都是业务理解、数据方案和应用落地。

### 2. 你怎么给跨境电商客户搭指标体系？

> 我会先从经营链路出发，而不是一开始就列很多指标。跨境电商一般可以拆成几个环节：流量获取、商品和 Listing、转化成交、广告投放、库存履约、售后退货、费用成本、利润和现金流。
>
> 第一层先确定北极星指标，比如销售额、净销售额、毛利、贡献利润、库存周转或现金回款。第二层拆过程指标，比如流量、转化率、客单价、广告 ACOS / ROAS、库存可售天数、缺货率、退货率、平台费用率。第三层再做诊断维度，比如平台、站点、店铺、SKU、ASIN、品类、供应商、负责人、渠道和时间。
>
> 指标体系不能只停留在定义，还要落到数据源和口径。比如 Amazon VC 的销售口径、订单口径、Retail 口径可能不同；组合品 SKU 和组成单品也要拆清楚；广告费用、仓储费、尾程费等有些需要分摊。只有把这些关系治理清楚，后面的分析和看板才可信。

### 3. 如果客户跨境电商数据很乱，你怎么开展？

> 我会先分三步走。第一步是业务目标确认，先问清楚客户最想解决的是利润看不清、库存不准、广告效率低，还是经营预警不及时。第二步是数据现状盘点，把 ERP、平台后台、广告系统、财务系统、人工维护表、线上导出表这些数据源摸清楚，包括更新频率、字段、负责人和可靠性。第三步是口径和主数据治理，比如 SKU / ASIN / 店铺 / 平台 / 供应商映射，父 SKU 和子 SKU，组合品和单品，费用分摊规则。
>
> 我不会一开始就直接做大而全的看板，因为数据口径没对齐时，看板越多争议越多。比较稳的方式是先选一个高价值主题，比如利润或库存，做出一条可信的数据链路，再逐步扩展到广告、退货、供应商和预警。

### 4. 你怎么理解神策的用户行为分析和跨境电商的结合？

> 我的理解是，神策更擅长从用户行为和客户经营角度帮助企业看清用户从访问、浏览、加购、下单、支付、复购到流失的全过程。放到跨境电商里，它可以补充传统经营 BI 不容易看到的用户行为链路。
>
> 比如传统 BI 可能更关注销售额、利润、库存和广告花费，但如果要解释为什么转化下降，就需要看用户从广告点击到落地页、商品页、加购、结算、支付这些环节在哪一步流失。这个时候漏斗分析、路径分析、用户分群、留存分析就很有价值。
>
> 我过去主要做经营数据和 BI 数据体系，对神策产品细节还需要熟悉，但我理解事件、用户、属性、指标和业务动作之间的关系，也能从业务问题反推需要采集什么数据、建立什么指标和看板。

### 5. 你做过 C 端用户分析吗？

> 做过。我在阿里巴巴 / 饿了么相关经历中，接触过比较多 C 端用户分析和运营分析场景，比如红包投放规则、用户标签、千人千面、用户是否会员、消费频次、客单价、价格敏感度等。
>
> 我的理解是，C 端分析的核心不是把用户当成一个整体，而是要分层经营。比如高频高价值用户、价格敏感用户、会员用户、沉默用户、新客和老客，适合的触达策略和优惠策略是不一样的。红包投放也不能只看发了多少券，而要看领取、使用、核销、下单、复购以及补贴成本是否合理。
>
> 这部分经验和神策的用户行为分析、标签体系、用户分群、客户旅程是能衔接的。放到跨境电商里，平台型业务可能受平台数据限制更多，但独立站、DTC 或品牌出海客户，就可以把访问、浏览、加购、下单、复购、会员和优惠策略结合起来做更细的用户经营。

### 6. RFM 和 AARRR 怎么理解？

> RFM 更偏用户价值分层，R 是最近一次消费，F 是消费频次，M 是消费金额。它可以帮助我们把用户分成高价值用户、潜力用户、价格敏感用户、沉睡用户等，然后针对不同人群设计不同的运营策略。
>
> AARRR 更偏增长链路，分别是获客、激活、留存、变现和推荐。它适合看用户从哪里来，进来后有没有完成关键行为，后续是否留存，能不能贡献收入，是否能带来传播或推荐。
>
> 面试里如果结合我的经历，我会说：在饿了么这种 C 端场景，RFM 可以帮助判断用户价值和红包策略，AARRR 可以帮助看从拉新到首单、复购、会员和长期留存的完整链路；放到跨境电商独立站，也可以用类似方法看用户从访问、加购、下单到复购的过程。

### 7. 你能给客户做培训和赋能吗？

> 可以。我理解客户培训不能只是介绍功能按钮，而是要围绕业务场景讲。比如跨境电商客户，如果我们要培训经营看板，我会先讲这个看板解决什么问题，比如利润下滑、库存积压、广告效率下降或转化异常；再讲应该看哪些指标、按什么维度下钻、发现异常后应该怎么处理。
>
> 我过去做内部 BI 推广时，也是这个思路。不同角色关注点不一样，管理层看整体利润和风险，运营看 SKU、广告、库存和转化，财务看费用和对账，供应链看库存和履约。所以培训要按角色设计，让每个人知道自己每天该看什么、异常出现后该找谁处理。

## 跨境电商核心业务模式速记

### 常见平台和模式

- Amazon Seller Central：卖家自运营，常见 FBA / FBM。
- Amazon Vendor Central：供应商模式，常见 PO、DI、DF，不同口径不能直接混用。
- 独立站 / DTC：如 Shopify，重点看流量、转化、复购、客单价和用户行为。
- 其他平台：Walmart、Wayfair、TikTok Shop、Temu、Shein、Shopee、Lazada、美客多等。
- 履约模式：FBA、海外仓、第三方仓、直发、平台仓。

### 核心经营链路

```text
流量获取 -> 商品曝光 -> 点击访问 -> 加购 -> 下单支付 -> 履约发货 -> 售后退货 -> 复购 / 留存
                       ↓
              广告费用 / 平台费用 / 物流仓储 / 成本 / 利润
```

### 重点指标

- 销售：GMV、净销售额、订单数、销量、客单价。
- 流量：曝光、点击、CTR、Sessions、CVR。
- 广告：Spend、广告销售额、ACOS、TACOS、ROAS。
- 库存：可售库存、在途库存、可售天数、周转率、超龄 / 滞销库存。
- 利润：毛利、贡献利润、平台费、FBA 费、仓储费、尾程费、促销费、Coupon、退款。
- 售后：退货率、RMA、差评率、评分、质量问题。
- 用户：新老客、复购率、留存、生命周期、用户分群、路径转化。

### Amazon 流量转化漏斗

```text
曝光 -> 点击 -> 商品页访问 -> 加购 -> 下单 -> 支付 / 发货 -> 评价 / 复购
```

面试表达：

> 如果 Amazon 销售下降，我会先按漏斗拆：曝光有没有下降、点击率有没有变差、访问量是否减少、转化率是否下滑、库存和 Buy Box 是否异常、广告 ACOS / TACOS 是否变化。这样才能判断问题到底来自流量、页面、价格、广告、库存还是评价。

## 面试前 15 分钟快速复习

1. 先看 1 分钟神策版自我介绍。
2. 背熟“有没有做过跨境电商”的回答。
3. 复习跨境电商指标链路：流量、转化、广告、库存、履约、售后、利润、用户。
4. 复习神策关键词：事件、用户、属性、漏斗、留存、路径、分群、标签、CDP、客户旅程。
5. 复习用户分析模型：RFM、AARRR、漏斗、留存、路径、用户分群。
6. 准备 4 个案例：经营 BI、自动化对账、数据预警、饿了么 C 端用户分析。
7. 反问面试官时重点问客户类型、岗位职责边界、交付方式和产品培训机制。

## 可反问面试官的问题

1. 这个岗位主要服务哪些行业客户？跨境电商客户占比大概高吗？
2. 这个岗位更偏客户数据分析咨询，还是更偏神策产品实施和使用培训？
3. 面试中提到跨境电商，是因为当前有相关客户项目，还是这个岗位长期会负责这个方向？
4. 团队对这个岗位的考核更看重客户满意度、项目交付、分析报告质量，还是产品使用深度？
5. 如果入职后要快速熟悉神策产品，公司内部是否有标准培训、案例库和行业方法论？

## 需要刻意避免的表达

- 不要说：“我主要是做 Power BI 报表。”
- 不要说：“神策产品我没用过，所以不太确定。”
- 不要说：“我比较内向，客户沟通可能不是强项。”
- 不要把跨境电商只讲成 Amazon 或销售额。
- 不要把数据治理讲成清洗脏数据，要讲成主数据、口径、分摊、质量和业务责任机制。

更好的表达：

> 我之前没有直接使用神策产品，但我做过完整的数据体系建设，也理解业务问题、指标体系、数据采集、数据治理和分析应用之间的关系。产品细节我可以通过培训和项目快速补齐，核心方法论是可以迁移的。
