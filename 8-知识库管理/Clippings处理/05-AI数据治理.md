# AI 时代的数据治理

原文：[[1-数据/数据治理/AI时代，数据治理到底应该怎么做？]]

## 一句话结论
AI Agent 让数据消费从人看报表变成 Agent 高频直取数据，治理重点应转为语义丰富、全模态覆盖、可被 AI 安全消费的数据产品化体系。

## 核心观点
- 口径不统一、字段含义不清会让 Agent 返回貌似正确的错误答案。
- 治理面临五变：低频报表消费转为高频直取，开发约定转为机器可理解语义，人脑知识转为知识工程，结构化转为全模态。
- 核心能力包括命名、描述、关系和语义标准化，以及统一指标语义层。
- 非结构化数据需要解析、切片、向量化、索引，并与结构化实体关联。
- 数据应服务化为带 SLA、权限、限流、监控、版本的 API，并注入业务上下文。

## 个人价值
直接对应 AI 问数、智能 BI、数据助手和企业知识库建设；可用于规划 AI-ready 数据平台，并以准确率、拒答率、口径冲突率和自助取数率衡量价值。

## 推荐动作
盘点 Top 100 高频表和核心指标，建立术语、口径、血缘、权限和问法示例；选择 1—2 个 Agent 场景做准确率基线和试点。

## 最小实践及验收
为 10 个核心指标补齐中文名、定义、公式、粒度、时间口径、责任人、示例问法和权限；接入一个问数 Agent。验收：固定测试集答案可追溯，口径冲突可拒答，元数据变更有版本记录。

## 需验证
文中 Gartner/IDC 比例及“准确率 60%→85%”等数字的来源和样本；语义层、元数据和 API 安全标准；文档解析、向量检索质量、隐私合规、成本和 SLA；Dataphin 相关内容需独立评估。

## 阅读建议
优先把文章当作治理路线图；从高频、可量化、低风险场景开始，不宜全量治理先行。
