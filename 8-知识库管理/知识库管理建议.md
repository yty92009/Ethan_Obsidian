# 知识库管理建议

> **历史设计文档**：本文是早期阶段的设计建议，其中目录结构和路径描述对应重组前的旧布局，不代表当前实际结构。现行管理规则、目录结构与能力边界以根目录《知识库管理项目说明》（v1.2 起）为准。

> 本文件记录知识库管理项目的完整设计建议。目标不是把所有资料自动总结一遍，而是让 AI 帮助筛选、压缩、归类、关联和转化知识；我只投入时间处理真正重要的内容。

## 一、总体定位

Obsidian 不应该只是收藏夹，而应该形成四层结构：

```text
原始资料
  ↓
AI 初步处理
  ↓
结构化知识
  ↓
可执行资产
```

### 1. 原始资料层

保存原始文章、课程、剪藏、代码、附件，不轻易改动。

典型内容：

- `7-收藏资料/Clippings/`
- `3-AI/AI Agents 教程/`
- 网页剪藏
- PDF、图片、视频
- 外部课程和源码

### 2. AI 处理层

AI 对原始资料完成：

- 内容摘要
- 主题分类
- 关键词提取
- 重要程度判断
- 与已有笔记的关联
- 是否值得深入研究的判断
- 生成待办或学习建议

建议放在：

- `8-知识库管理/99-收件箱/`
- `3-AI/12-AI对话沉淀/`
- 后续可增加的 `AI处理队列/`

### 3. 结构化知识层

把真正值得长期保留的内容整理到正式专题中：

- `1-跨境电商与经营分析/02-BI与数据仓库/`
- `4-数据分析/行业场景/跨境电商/`
- `4-数据分析/行业场景/跨境电商/`
- `4-数据分析/行业场景/跨境电商/`
- `3-AI/06-自动化-RPA-AI-Agent/`
- `2-BI/项目案例/`
- `6-面试与职业发展/10-面试-职业发展/`

### 4. 可执行资产层

最终不要只留下摘要，还要尽可能形成：

- 方法论
- 检查清单
- SOP
- 项目模板
- 面试回答
- SQL / Python 代码
- 指标定义
- 决策规则
- 待办事项
- 个人观点

这是知识库真正产生价值的地方。

## 二、AI 不要只做摘要机器

单纯总结文章，长期效果通常不好，因为容易得到很多“看过了，但没有真正变成能力”的摘要。

每篇资料更适合让 AI 回答以下问题：

1. 这篇内容主要解决什么问题？
2. 哪些内容是事实，哪些是作者观点？
3. 对我当前工作有什么价值？
4. 和我已有的哪些知识相关？
5. 是否存在重复内容？
6. 我是否需要马上阅读？
7. 如果不阅读全文，我至少应该知道什么？
8. 是否值得转化成方法、模板、项目或待办？
9. 未来什么场景下可以检索它？
10. 下一步是否需要实践？

AI 的任务应从：

> 帮我总结这篇文章。

升级为：

> 帮我判断这篇资料是否值得我投入时间，以及它应该如何进入我的知识体系。

## 三、知识处理卡片模板

为收藏资料统一生成一张轻量卡片，建议包含：

```markdown
---
type: source
status: inbox
importance: medium
source_type: article
topic:
  - 待分类
processing_status: pending
created: YYYY-MM-DD
source_path:
related_notes: []
next_action: triage
---

# 标题

## 一句话结论

## 这篇资料解决什么问题

## 核心观点

- 
- 
- 

## 对我的价值

### 对当前工作的价值

### 对职业发展的价值

### 对现有项目的价值

## 与已有知识的关系

- 关联笔记：
- 是否重复：
- 可补充到：

## 是否值得深入阅读

- [ ] 值得完整阅读
- [ ] 只看摘要即可
- [ ] 需要实践
- [ ] 暂时归档

## 可转化资产

- [ ] 方法论
- [ ] SOP
- [ ] 项目方案
- [ ] 面试素材
- [ ] 代码或脚本
- [ ] 待办事项

## AI 摘要

## 我的最终判断

## 后续动作
```

最重要的部分是：

- 是否值得深入阅读
- 可转化资产
- 我的最终判断

这样可以避免收藏越来越多，但真正吸收的内容越来越少。

## 四、优先级筛选机制

不要按收藏时间顺序处理全部资料。让 AI 按以下维度判断：

| 维度 | 判断问题 |
|---|---|
| 与当前工作相关度 | 是否直接帮助跨境电商、BI、P&L、数据治理？ |
| 与职业目标相关度 | 是否帮助成为数据负责人、经营分析负责人？ |
| 可实践程度 | 是否能转化成项目、代码、模板或流程？ |
| 独特性 | 是否只是重复常见观点？ |
| 时效性 | 是否已经过时？ |
| 阅读成本 | 预计需要投入多少时间？ |

建议优先级：

```text
S级：马上处理，和当前工作或求职直接相关
A级：值得近期处理，可以转化为项目或能力
B级：保留摘要，暂时不深入
C级：仅归档，不再投入时间
```

结合当前知识库，建议优先级如下：

### S 级

- 跨境电商 P&L
- Amazon VC 财务风控
- 数据治理与指标体系
- Power BI 底层化
- AI Agent 在经营分析中的应用
- 自动化
- 面试和职业发展材料

### A 级

- RAG
- NL2SQL
- LangGraph
- 数据质量和自动化
- Airflow
- 供应链智能体

### B 级

- 一般性的技术文章
- 重复的财务分析文章
- 工具介绍
- 泛泛而谈的职场文章

### C 级

- 仅作收藏但与当前方向无关的资料
- 内容重复且没有新方法的资料
- 需要很高成本、近期无法实践的资料

## 五、用状态管理现有目录

不建议一开始大规模移动已有文件。先通过 YAML 属性管理状态。

推荐字段：

```yaml
---
type: source
status: inbox
topic: ai-agent
importance: high
processing: summarized
knowledge_level: source
related_project:
next_action: practice
review_date: YYYY-MM-DD
---
```

推荐状态：

```text
inbox       待处理
triaged     已分类
summarized  已总结
linked      已关联
converted   已转化为正式知识
practiced   已实践
archived    已归档
```

推荐知识类型：

```text
source       原始资料
summary      AI 摘要
concept      概念知识
method       方法论
sop          操作流程
project      项目经验
case         案例
decision    决策记录
prompt       提示词
reference    参考资料
```

## 六、AI 资料处理流水线

```text
收藏资料
  ↓
自动识别文件类型
  ↓
提取正文
  ↓
生成短摘要
  ↓
判断主题和重要性
  ↓
查找相似笔记
  ↓
识别重复内容
  ↓
推荐归档位置
  ↓
生成知识卡片
  ↓
生成待办或实践任务
  ↓
人工确认
  ↓
合并进正式知识库
```

### AI 可以自动做的事情

- 读取 Markdown、PDF、Word、TXT、网页剪藏
- 提取标题、作者、来源和时间
- 生成摘要
- 提取关键词
- 判断主题
- 推荐关联笔记
- 检测重复
- 生成目录和标签
- 推荐存放位置
- 生成复习问题
- 生成实践任务

### 不建议 AI 自动做的事情

- 自动覆盖正式笔记
- 自动删除所谓重复内容
- 自动修改个人经历
- 自动把文章观点写成个人真实经验
- 自动把未经验证的规则写进 P&L 或财务口径
- 自动把外部资料当成项目事实

正式写入知识库前，应保留人工确认步骤。

## 七、三个 AI 工作模式

### 模式一：快速筛选

适合没有时间时使用，每篇资料只处理几十秒到几分钟。

输出：

- 一句话总结
- 重要性
- 是否值得阅读
- 3 个核心观点
- 是否与已有知识重复
- 推荐下一步

目标：

> 我现在要不要花时间看它？

### 模式二：深度归纳

适合真正重要的资料。

输出：

- 结构化摘要
- 核心概念
- 方法论
- 优缺点
- 适用场景
- 与现有项目的关系
- 可以补充到哪些正式笔记
- 需要验证的地方

目标：

> 这篇资料如何变成我的知识？

### 模式三：实践转化

适合 AI、数据、BI 和自动化内容。

输出：

- 一个最小实践任务
- 所需数据或工具
- 操作步骤
- 验收标准
- 可能的项目应用场景
- 是否值得沉淀成项目案例

目标：

> 我怎样把这篇资料变成能力？

## 九、第一阶段 MVP

第一阶段只做五个功能：

### 1. 扫描资料

读取：

- Markdown
- PDF
- Word
- TXT
- CSV
- JSON

暂时不处理图片、视频和大型源码目录。

### 2. 自动生成资料卡片

每篇原始资料生成：

- 一句话摘要
- 主题
- 重要程度
- 关键词
- 推荐去向
- 是否值得深入

### 3. 建立待处理队列

```text
8-知识库管理/99-收件箱/
  待筛选/
  已筛选/
  待实践/
  待归档/
```

### 4. 查找相似笔记

优先利用现有 `vault-curate` 插件的语义检索能力，避免重复建设一套向量检索系统。当前插件具备：

- BM25 + Embedding
- CJK 支持
- 自动索引
- 语义路径和关系图能力

### 5. 人工确认后写入正式目录

AI 只生成候选内容，不直接覆盖正式笔记。

## 十、第二阶段可增加的能力

第一阶段稳定后，再考虑：

- 批量处理命令
- Obsidian 命令面板
- 自动生成日报 / 周报
- 标签和 YAML 自动补全
- 重复笔记检测
- 主题知识地图
- 间隔复习
- 问答式检索
- 基于项目的上下文助手
- 每周自动生成学习建议
- “这篇资料对我当前项目有什么帮助”功能

最终可以形成：

```text
知识筛选助手
资料总结助手
知识归档助手
项目记忆助手
面试准备助手
学习计划助手
数据分析助手
```

## 十一、事实、观点和个人经验必须分开

知识库中同时存在：

1. 外部文章观点
2. 教程和示例代码
3. 个人项目经验
4. 面试表达材料
5. AI 生成内容
6. 正式业务规则

建议在每篇笔记中明确：

```text
来源类型：外部资料 / 我的经验 / AI整理 / 项目事实
可信程度：待验证 / 参考 / 已验证 / 正式规则
适用范围：学习参考 / 面试表达 / 真实项目 / 当前生产
```

必须注意：

- 外部文章中的数字不能直接作为个人项目结果
- 教程代码不能直接当作生产方案
- AI 总结不能自动成为业务规则
- 面试话术不能反过来覆盖真实经历

这对 P&L、财务风控和面试资料尤其重要。

## 十二、针对当前 Vault 的执行路线

### 第一优先级：建立统一入口

把个人档案、业务主线、面试知识库和 AI 学习项目串起来。

### 第二优先级：建立收藏资料筛选机制

让 AI 帮助判断：

> 值不值得看、应该放哪里、能不能转化成能力。

### 第三优先级：优先处理职业主线资料

重点处理：

- 跨境电商经营分析
- P&L
- Amazon VC
- 数据治理
- Power BI
- AI Agent
- 自动化
- 面试与职业发展

### 第四优先级：把知识转成项目资产

每处理一批资料，至少产出一种可复用资产：

- 一页方法论
- 一张流程图
- 一份检查清单
- 一个项目案例
- 一个面试回答
- 一个实践任务
- 一段可运行代码

### 第五优先级：最后再做目录重构

先通过标签、状态和索引管理知识库，使用一段时间后，再根据真实检索习惯决定是否调整目录。

## 十三、项目最终形态

最适合当前知识库的产品形态是：

> **Obsidian 作为知识存储层，AI 作为筛选和归纳层，项目模板和实践任务作为知识转化层。**

第一版应优先做成“批量处理收藏资料并生成知识卡片”的工具，而不是复杂的全自动知识库系统。这样投入小、风险低，也最容易验证是否真的节省时间。
