# 应急自救手册

> 目的：不依赖 AI 会话，自己完成"看历史、恢复文件、重新扫描"三类操作。命令在 PowerShell / Git Bash 中、于 `D:\Ethan\Ethan` 目录下执行。
> 前提：本库已启用 git 版本控制；`.gitignore` 排除了 `*.mp4` 和 Obsidian 工作区临时文件，它们不在版本控制内。

## 一、五条核心命令

```powershell
# 1. 看提交历史（每次结构变更都有提交，注释写明做了什么）
git log --oneline

# 2. 看当前改了哪些文件（提交前自查）
git status

# 3. 把某个文件恢复到某次提交时的样子（<提交号> 来自 git log，文件用库内相对路径）
git checkout <提交号> -- "路径/文件名.md"

# 4. 整库回滚到某次提交（会丢弃其后所有改动，慎用；先复制一份当前目录再执行）
git reset --hard <提交号>

# 5. 提交当前全部改动（日常备份习惯：完成一批处理后执行一次）
git add -A; git commit -m "说明这次做了什么"
```

找回"曾经存在但现在找不到的提交"：`git reflog`（列出所有 HEAD 移动记录，reset 错了也能从这里找回提交号）。

## 二、三个常见事故场景

### 场景 1：误删了笔记或目录

1. `git status` 确认删除（显示 `D`）。
2. `git checkout HEAD -- "路径/文件名.md"`（从最近一次提交恢复单个文件）。
3. 整目录误删：`git checkout HEAD -- "目录名/"`；不确定路径时先 `git log --diff-filter=D --name-only` 查最近被删的文件清单。

### 场景 2：批量改写改坏了（如链接替换出错）

1. `git log --oneline` 找到改坏之前的提交号。
2. 单文件恢复用命令 3；大范围损坏时：先整库复制一份作保险（`D:\Ethan\Ethan` 复制到 `D:\Ethan\Ethan-backup-日期`），再 `git reset --hard <好提交号>`，最后从保险副本里找回 reset 之后产生的新内容。
3. 恢复后跑一遍扫描（见下）确认状态。

### 场景 3：怀疑链接大量失效（移动/改名后）

1. 用 Obsidian 自带：设置 → 核心插件开启"反向链接"；或搜索框搜 `[[` 配合"文件名不存在"提示逐个看。
2. 让 AI 会话执行全库链接扫描（说明文档 §15 的检索流程），给出失效清单后逐条修。
3. 修完必须再做一次 `git add -A; git commit`，把修复本身存进历史。

## 三、定期自检（每月一次，5 分钟）

1. `git log --oneline | head -20`：确认最近有提交、注释能看懂当时做了什么。
2. 删除一条测试：新建临时文件 → 提交 → 删除 → 用命令 3 恢复，验证恢复流程真的会走。
3. 核对 `7-收藏资料/Clippings/` 数量是否在下降（处理一个少一个）；不降说明消化流程停了。

## 五、什么时候该找 AI 而不是自己动手

- 批量路径改写、全库链接修复、结构重组——AI 用映射表脚本做，手改容易漏。
- 涉及业务口径、项目事实的文件内容判断——人审，AI 只出候选。
- 本手册命令执行报错且看不懂时：**先 `git status` 截图/记录现场，不要连敲命令试错**。
